# Contributing

Leonardo Tales Constitution v1.1.1 governs internal project decisions.

Once the contribution channel opens, use an issue for ordinary proposals and a focused pull request for the agreed change. Explain the affected Task, approval or execution boundary and verify the change on Linux using the pinned install, strict typecheck and test commands. Include a focused synthetic regression case when changing behavior. Maintainers review scope, verification, license compatibility and applicable attribution before accepting contributions. [Developer quickstart](README.md) · [Project boundary](PROJECT_BOUNDARY.md) · [License scope and attribution](NOTICE.md)

Keep private logs, identities, credentials, internal correspondence and real user data out of contributions. Use the proposed private reporting process for suspected vulnerabilities after it has been enabled and verified. [Security policy](SECURITY.md)

These project rules guide contribution review. Downstream rights follow the applicable licenses.
